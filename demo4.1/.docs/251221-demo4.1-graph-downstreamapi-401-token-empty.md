# Retrospective: Microsoft Graph `IDownstreamApi` 401 ("Access token is empty")

## Symptom

When calling Microsoft Graph via `IDownstreamApi`, Graph returned:

- `401 Unauthorized`
- Error payload included: `"code":"InvalidAuthenticationToken"` and `"message":"Access token is empty."`

## What actually went wrong (root cause)

`Microsoft.Identity.Web` expects downstream API scopes to be configured as a **collection** (an array) in configuration.

We had configured:

- `DownstreamApis:MicrosoftGraph:Scopes` as a **single JSON string**, not an array.

Because the `Scopes` value did not match the expected shape, it could be bound as empty/null for the downstream API options. With no effective scopes to request, `IDownstreamApi` ended up sending a request without a bearer token, and Microsoft Graph correctly rejected it with “Access token is empty.”

Official docs show `Scopes` as an array (example includes `Scopes`: `["user.read"]`):

- `https://learn.microsoft.com/en-us/entra/identity-platform/scenario-web-app-call-api-app-configuration?tabs=aspnetcore`

## Why Weather worked while Graph failed

Weather calls were working because the Weather flow in this demo was implemented explicitly using `ITokenAcquisition` + a named `HttpClient` + manually setting the `Authorization: Bearer <token>` header (and the YARP proxy path does the same). That approach parses scopes as either a string or an array.

Graph calls, by contrast, were relying on `IDownstreamApi` to:

1. Read `DownstreamApis:MicrosoftGraph` options (including scopes),
2. Acquire the token, and
3. Attach the bearer token.

So only Graph was sensitive to the config shape mismatch.

## Fix applied in this repo

1) Configure scopes as arrays in `demo4.1/SaaS.Frontend/SaaS.Frontend/appsettings.json`:

- `DownstreamApis:WeatherApi:Scopes`: `[ "api://<backend-client-id>/Weather.Get" ]`
- `DownstreamApis:MicrosoftGraph:Scopes`: `[ "User.Read" ]`

2) Update the README user-secrets guidance to set arrays correctly:

- `dotnet user-secrets set "DownstreamApis:MicrosoftGraph:Scopes:0" "User.Read"`

3) Make `GraphService` resilient by reading scopes from configuration (array-first, string fallback) and setting `options.Scopes` explicitly.

## Permissions note (Graph `/me`)

The `GET /me` endpoint requires a delegated permission such as `User.Read` (minimum for basic profile in typical setups).

- Microsoft Graph “Get user” (`/me`) docs: `https://learn.microsoft.com/en-us/graph/api/user-get?view=graph-rest-1.0&tabs=http`
