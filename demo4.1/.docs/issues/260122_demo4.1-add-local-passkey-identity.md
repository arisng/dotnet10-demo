# Task: Add local identity + passkey stack in SaaS.Frontend

## Objective
Introduce local Identity + passkey authentication alongside Entra OIDC in demo4.1's BFF, matching the demo4 hybrid identity story.

## Tasks
- [x] Add ASP.NET Core Identity with `IdentitySchemaVersions.Version3` and EF Core store in `SaaS.Frontend` (or shared auth component if preferred).
- [x] Wire passkey endpoints and identity UI routes (`MapAdditionalIdentityEndpoints`, `/Account/*`) in the BFF.
- [x] Ensure InteractiveAuto flow remains prerender-safe with the new identity services.
- [x] Update the sign-in surface to expose local/passkey options in addition to Entra.
- [ ] Verify that local auth can sign in and reach protected BFF/API routes.

## Notes
- Local Identity uses `/Account/*` endpoints; Entra OIDC uses MIW `/MicrosoftIdentity/Account/*` endpoints.
- Normalized `returnUrl` to base-relative paths before passing into `MicrosoftIdentity/Account/SignIn` to avoid absolute URL issues.

## Acceptance Criteria
- [x] Local cookie-based identity is enabled with passkey endpoints.
- [x] UI exposes local/passkey sign-in alongside Entra.
- [ ] Local login works end-to-end without breaking existing Entra flow.
