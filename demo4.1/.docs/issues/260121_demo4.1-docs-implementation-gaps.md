# Demo4.1 Documentation Gaps vs Implementation

**Date:** 2026-01-21
**Type:** Technical Issue
**Severity:** Medium
**Status:** Resolved

---

## Problem

Demo4.1 documentation claims do not fully match the implemented behavior, which can mislead readers about where OBO is implemented, what the YARP proxy routes cover, and how Graph tokens are acquired.

## Root Cause

The README was updated with higher-level architecture statements, but specific code references and routing details were not aligned with the final implementation.

## Solution

Update demo4.1 README to align with implementation:

1. **OBO Evidence Link**: Point the OBO flow evidence to the BFF implementation where tokens are acquired, not the backend.
   - Evidence: `SaaS.Frontend/Program.cs` (AddDownstreamApi + YARP transform)
2. **YARP Proxy Scope**: Clarify the proxy only maps `/api/proxy/weather/{**catch-all}` and a single weather cluster, not `/api/*`.
3. **Token Acquisition Wording**: Clarify that the proxy transform acquires Weather tokens only; Graph tokens are acquired in `GraphService` via `IDownstreamApi`.

## Lessons Learned

- Documentation should reference the specific implementation files responsible for authentication/token flows.
- Proxy route descriptions must match actual route patterns to avoid confusion.

## Prevention

- [ ] Add a pre-merge checklist item to validate README claims against code.
- [ ] Require explicit file references for auth/token flow descriptions.
