# Convert solution to SLNX format (Demo3.BffRbac)

**Date:** 2025-11-21
**Issue Type:** Process Improvement
**Severity:** Medium
**Status:** Documented

## 📋 Summary

We migrated `Demo3.BffRbac.sln` to the new XML `.slnx` format (Visual Studio / .NET 10+). The migration was executed using `dotnet sln <solution>.sln migrate`. The CLI-generated `Demo3.BffRbac.slnx` builds successfully in the local development environment; no solution filters (`*.slnf`) reference needed updates.

## 🔍 Analysis / Context

### Background

- In .NET 10 the default solution file format can be `.slnx` (XML-based) in place of the traditional `.sln` file.
- The new format addresses maintainability and merge conflict concerns and is supported by `dotnet sln` and MSBuild 17.12+.

### Actions taken

- Confirmed SDK/tooling: `dotnet --version` = 10.0.100.
- Executed `dotnet sln Demo3.BffRbac.sln migrate` from `demo3` folder.
- Verified `Demo3.BffRbac.slnx` was created at `demo3/Demo3.BffRbac.slnx` and listed projects.
- Built the new `.slnx` successfully with `dotnet build`.
- Searched the repo for `.slnf` files and references to the old `.sln` file (none found referencing the file), so no filter updates were required.

### Observations

- The newly generated `.slnx` is minimal and lists the solution projects configured for the solution.
- The original `.sln` was left in place (no deletion nor changes were made).

## ✅ Resolution / Decision

- **Decision**: Generate and keep `Demo3.BffRbac.slnx` to adopt the new simpler solution format for demo3.
- **Actions taken**: `dotnet sln Demo3.BffRbac.sln migrate` (no automated commit was created to the repo; the `.slnx` file exists untracked in the working directory).
- **Rationale**:

  - The new `.slnx` format reduces solution file verbosity, improves readability, and reduces merge conflicts.
  - Building using `.slnx` works with the project's .NET tooling (SDK 10.0.100 and MSBuild 17.x).

## 📚 Lessons Learned

- The `dotnet sln migrate` command provides an easy way to migrate — and the new `.slnx` is build-compatible with the current SDK.
- Solution filters (`.slnf`) are tied to a specific solution filename; if `.slnf` is used, update them to reference the new `.slnx` name.
- If the team prefers `.slnx` format, decide whether to remove or keep the old `.sln` file; Microsoft recommends avoiding keeping both files in the repo long term.

## 🛠️ Prevention / Implementation

- **Implementation options** (pick one or a mix):

  1. Add `Demo3.BffRbac.slnx` to Git and inform the team. Update CI, scripts, and team docs to use the `.slnx` file if necessary. (Preferred path unless a team-wide policy requires `.sln`.)

  2. If backward-compatibility needed: Use a short period keeping both formats, but add a sync workflow or use `dotnet-sln-sync` if you need to keep both types in sync in the repo.

  3. If adopting `.slnx`, remove the old `.sln` file after confirming all tooling and CI references were updated and all teammates are migrated.
